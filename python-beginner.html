    Module 1

    Setup and your first program

    Install Python, run code two different ways, and learn to read an error message without panic.

    About 45 minutes

    Python is a programming language: a way of writing instructions that a computer can follow. It is popular because it reads almost like English, it has a huge collection of ready-made tools, and it is used for websites, data analysis, automation and AI. When you write Python you are writing plain text in a file. A program called the interpreter reads that text from top to bottom and does what each line says.

    Why an interpreter matters
    Because Python is interpreted, you can run a single line and see the result immediately. That fast feedback loop is why Python is a good first language: you try something, you see what happens, you adjust.

    Installing Python

    Download the latest Python 3 from python.org/downloads. Avoid Python 2; it is retired and many tutorials that use it will not run on a modern machine. The steps differ slightly by system.

    SystemHow to installCommand to use
    WindowsRun the installer from python.org. Tick 'Add python.exe to PATH' on the first screen, then choose Install Now.python or py
    macOSUse the installer from python.org, or run brew install python if you use Homebrew.python3
    LinuxMost distributions include it. If not: sudo apt install python3 python3-pip python3-venv on Ubuntu or Debian.python3
    The PATH checkbox
    On Windows, forgetting to tick 'Add python.exe to PATH' is the number one beginner problem. Afterwards the terminal says 'python' is not recognized as an internal or external command. Fix it by running the installer again, choosing Modify, and enabling the PATH option, or by using the py launcher.

    Open a terminal (Command Prompt or PowerShell on Windows, Terminal on macOS and Linux) and check that the install worked. The exact version number on your machine will be different from the example below, and that is fine as long as it starts with 3.

    Two ways to run Python

    The REPL (read, evaluate, print, loop) is an interactive prompt. Type python in the terminal and you will see >>>. Each line you type runs immediately. It is perfect for experiments and quick maths. Leave it with exit().

    A script is a file that ends in .py. You save your instructions there and run the whole file with python filename.py. Scripts are how you build real programs because you can save, edit, share and rerun them.

    Choosing an editor

    You can write Python in Notepad, but a code editor makes life much easier. Visual Studio Code (VS Code) is free and a good choice. Install it, then add the Python extension by Microsoft from the Extensions panel. Create a folder called ciphercode-python, open it in VS Code with File, Open Folder, and create a new file named hello.py. Press the play button at the top right to run it, or use the terminal inside VS Code with python hello.py.

    Your first program

    The traditional first program shows a message. In Python that is one line. Read it piece by piece: print is a function, a named action that Python already knows. The round brackets hold what you hand to the function, called the argument. The text in quotes is a string, which is how Python represents words and sentences.

    print can take several values separated by commas. It puts a space between them. You can also change what goes between values with sep and what goes at the end with end.

    Comments

    A line that starts with # is a comment. Python ignores it completely. Comments are notes to humans: why the code exists, what a tricky part does, or what you plan to do next. Good comments explain why, not just what. Write comments for the person who will read your code in six months, which is usually you.

    Run it often
    Run your code after every two or three lines. When a program is small, an error can only be in the line you just added. When you write thirty lines before running, you have thirty suspects.

    Reading error messages

    You will see errors every day as a programmer, so learn to read them calmly. An error is Python telling you exactly what it could not understand. Read it from the bottom up: the last line names the kind of error and gives a reason, and the lines above show where it happened.

    ErrorWhat it meansTypical cause
    SyntaxErrorPython cannot understand how the line is writtenMissing bracket or quote, a missing colon
    NameErrorYou used a name Python does not knowA typo in a name, or using a variable before creating it
    IndentationErrorSpaces at the start of a line are wrongMixed tabs and spaces, or an unexpected indent
    TypeErrorA value is the wrong kind for the actionAdding a number to text
    Beginner traps to avoid
    Save your file before running it, otherwise you run the old version. Do not name your file random.py or math.py, because it will hide Python's own modules later. Use straight quotes " ", not curly quotes copied from a word processor, which cause SyntaxError: invalid character.

    You now have everything needed to move forward: Python installed, an editor, two ways to run code, and a method for reading errors. The next module introduces variables, which let your programs remember things.

    Remember this

    • Python is run by an interpreter that reads your .py file from top to bottom.
    • Use the REPL for quick experiments and scripts for real programs.
    • print() shows values; sep and end change how it formats them.
    • Comments start with # and are ignored by Python.
    • Read errors from the bottom line up: it names the problem.

    Check yourself

    Which command checks the installed Python version?

    The --version flag prints the version and exits. On macOS and Linux you usually type python3 --version.

    What does Python do with a line starting with #?

    A # starts a comment. Python skips everything after it on that line.

    You see 'NameError: name total is not defined'. What is the most likely cause?

    NameError means Python does not know that name. Check spelling and make sure the variable is created before it is used.

    Module 2

    Variables, types and operators

    Give values names, understand the basic data types, do arithmetic, and read input from a user.

    About 55 minutes

    A program is mostly about handling data: prices, names, marks, scores. To work with data you need a way to remember it. A variable is a name that points to a value stored in the computer's memory. You create one with the = sign, which in Python means assign, not 'equals'. Read price = 15 as 'let the name price refer to the value 15'.

    A mental model: labels, not boxes
    Many people picture a variable as a box holding a value. A better picture is a sticky label attached to a value. You can move the label to a different value at any time, and two labels can point to the same value. This model will save you from confusion when we reach lists.

    Naming rules and style

    • Names can contain letters, digits and underscores, but cannot start with a digit: score1 is fine, 1score is a SyntaxError.
    • Names are case-sensitive: Marks and marks are two different names.
    • You cannot use Python's reserved words such as if, for, class, True or None.
    • The Python style is snake_case: lowercase words joined by underscores, like total_price.
    • Choose names that say what the value is: cups_sold beats x.

    The basic types

    Every value has a type that decides what you can do with it. You can ask Python with the built-in type() function. These five are the foundation.

    TypeMeaningExamples
    intWhole numbers, any size7, -3, 1_000_000
    floatNumbers with a decimal point3.14, -0.5, 2.0
    strText, in quotes"chai", '42'
    boolTruth values, exactly twoTrue, False
    NoneType'Nothing here yet', the single value NoneNone
    Underscores in big numbers
    Python lets you write 1_000_000 for readability. The underscores are ignored, so it is the same as 1000000.

    Arithmetic operators

    Operators are symbols that combine values. Besides the usual + - * /, Python has three that beginners should learn early: // (floor division, which drops the fraction), % (remainder, also called modulo) and ** (power). Note that / always returns a float, even when the answer is whole.

    Converting between types

    Python will not guess what you mean when types are mixed. Adding a number to text is an error, because it is unclear whether you want addition or joining. You convert explicitly with int(), float(), str() and bool().

    f-strings: text with values inside

    An f-string is a string that starts with f before the opening quote. Anything inside curly braces { } is evaluated as Python and placed into the text. No conversions needed. After a colon inside the braces you can control formatting, such as :.2f for two decimal places or :, for thousands separators.

    Reading input

    input() pauses the program, shows a prompt, waits for the user to type and press Enter, and hands back what they typed. The key rule: input() always returns a str, even if the user types digits. If you want to do arithmetic, convert the result.

    Common mistakes
    Using = when you meant to compare (comparison uses ==, covered next module). Doing arithmetic on the result of input() without converting it. Expecting int(9.99) to round up: it truncates to 9. Giving a variable the name of a built-in such as type, list or sum, which silently breaks those functions later.

    Remember this

    • A variable is a name attached to a value; assignment evaluates the right side first.
    • The core types are int, float, str, bool and None; type() tells you which one you have.
    • / always gives a float, // drops the fraction, % gives the remainder, ** is power.
    • Convert explicitly with int(), float() and str(); Python will not mix types for you.
    • f-strings place values inside text, and input() always returns a string.

    Your turn

    A cricket team scored 186 runs in 20 overs. Store these in variables, calculate the run rate (runs per over) and print it to 2 decimal places in a sentence. Also print how many complete 10-over blocks fit in 20 overs using floor division.

    run_rate = runs / overs. Use {run_rate:.2f} inside an f-string. For blocks use overs // 10.

    Check yourself

    What does 17 % 5 evaluate to?

    17 divided by 5 is 3 with a remainder of 2. The % operator returns that remainder.

    What type does input() always return?

    input() gives back text every time. Convert with int() or float() if you need a number.

    Which is a valid variable name?

    Names cannot start with a digit, cannot contain hyphens, and cannot be reserved words like class.

    Module 3

    Strings: working with text

    Index, slice, search and clean text, and understand why strings can never be changed in place.

    About 55 minutes

    A string is a sequence of characters: letters, digits, spaces, symbols, emoji. Names, messages, passwords, file paths and web addresses are all strings. Text handling is a huge part of real programs, so Python gives strings a rich set of tools. You write a string with single quotes, double quotes, or triple quotes for text that spans several lines.

    Indexing: picking one character

    Every character in a string has a position called an index. Python counts from zero, so the first character is at index 0. Negative indexes count from the end: -1 is the last character. Think of the index as 'how many steps from the start', and then zero makes sense, because the first character is zero steps away.

    CharacterCIPHER
    Index012345
    Negative index-6-5-4-3-2-1

    Slicing: picking a piece

    A slice takes a range of characters using [start:stop]. It includes start and stops before stop. Leave out start to begin at the front, leave out stop to go to the end. A third number is the step: [start:stop:step].

    Why stop is excluded
    Because s[:3] + s[3:] gives back the whole string with no overlap and no gap, and because the length of s[a:b] is simply b - a. Half-open ranges avoid many off-by-one bugs.

    Strings are immutable

    Immutable means you cannot change a string after it is created. You can read any character, but you cannot assign to one. To 'change' text you build a new string and, if you want, point the variable at it.

    Methods: built-in tools for strings

    A method is a function attached to a value, called with a dot: text.upper(). String methods never change the original (it is immutable). They return a new string, so remember to store or print the result. Here are the ones you will use constantly.

    MethodWhat it doesExample result
    upper() / lower()Change case'chai'.upper() gives 'CHAI'
    title() / capitalize()Capitalise words / first letter'masala chai'.title() gives 'Masala Chai'
    strip()Remove spaces from both ends' hi '.strip() gives 'hi'
    replace(old, new)Swap text'a-b'.replace('-', '+') gives 'a+b'
    split(sep)Break into a list'a,b,c'.split(',') gives ['a', 'b', 'c']
    sep.join(list)Join a list into a string'-'.join(['a','b']) gives 'a-b'
    find(x)Index of x, or -1 if absent'hello'.find('l') gives 2
    count(x)How many times x appears'banana'.count('a') gives 3
    startswith(x) / endswith(x)Test the beginning / end'a.py'.endswith('.py') gives True
    isdigit() / isalpha()Check what it contains'123'.isdigit() gives True

    Searching with in

    The in operator asks 'is this piece of text inside that one?' and answers True or False. It is case-sensitive, so lower-case both sides when you want a relaxed match.

    Formatting recap and a worked example

    You met f-strings last module. They also align text, which is useful for tables: {name:<10} left-aligns in 10 spaces, {value:>8.2f} right-aligns a float. Let us combine slicing, methods and formatting in a small program that tidies a messy name and builds a username.

    Common mistakes
    Calling text.upper() without storing the result and expecting text to change. Using = inside a string comparison instead of ==. Forgetting that find() returns -1 (which is truthy) when nothing is found, so check == -1 or just use in. Mixing up len(s) with the last index; the last index is len(s) - 1.

    Remember this

    • Strings are sequences of characters with indexes starting at 0; negatives count from the end.
    • Slices [start:stop:step] include start and exclude stop, and never raise errors for out-of-range stops.
    • Strings are immutable: methods return new strings and leave the original unchanged.
    • split() and join() convert between a string and a list of words.
    • Use in to test whether text contains other text; remember it is case-sensitive.

    Your turn

    Use strip() and title(), then split() to get the list of words. words[0] and words[-1] give first and last.

    Check yourself

    What does 'CIPHERCODE'[2:5] give?

    Indexes 2, 3, 4 are P, H, E. The slice stops before index 5.

    After text = 'hello'; text.upper(), what is text?

    Strings are immutable. upper() returns a new string; the original stays 'hello' unless you store the result.

    Which expression reverses a string s?

    A step of -1 walks backwards through the whole string. Strings have no reverse() method.

    Module 4

    Making decisions with conditions

    Compare values, combine tests with and/or/not, and make programs choose a path with if, elif and else.

    About 50 minutes

    So far your programs run every line, top to bottom, every time. Real programs need to decide: if the password is right, let the user in; if the marks are above 90, give an A grade. Decisions are built from two ingredients: a condition, which is an expression that is either True or False, and an if statement that runs code only when the condition is true.

    Comparison operators

    Comparisons produce a bool. The most important thing to remember: = assigns, == compares.

    OperatorMeaningExampleResult
    ==equal to5 == 5True
    !=not equal to5 != 3True
    > / <greater / less than3 > 5False
    >= / <=greater or equal / less or equal5 >= 5True

    The if statement and indentation

    An if line ends with a colon :. The lines that belong to it are indented (moved right) by the same amount, conventionally 4 spaces. That indented group is called a block. Python uses indentation, not brackets, to know where a block starts and ends. When the indentation goes back to the left, the block is finished.

    Indentation and colon errors
    Forgetting the colon gives SyntaxError: expected ':'. Forgetting to indent gives IndentationError: expected an indented block after 'if' statement. Mixing tabs and spaces gives TabError. Set your editor to insert 4 spaces when you press Tab, and never mix the two.

    if, elif and else

    else handles 'everything otherwise'. elif (short for 'else if') adds extra questions in between. Python checks them from the top and runs the first block whose condition is true, then skips the rest. Order therefore matters: put the most specific or highest tests first.

    Combining conditions: and, or, not

    OperatorTrue whenExample
    andboth sides are trueage >= 18 and has_id
    orat least one side is trueday == 'Sat' or day == 'Sun'
    notflips True and Falsenot is_raining
    A common beginner bug with or
    if day == 'Sat' or 'Sun': looks right but is always true, because 'Sun' on its own counts as true (non-empty text). Write the full comparison on both sides, or use day in ('Sat', 'Sun').

    Truthiness

    An if does not strictly need a bool. Python treats some values as falsy: False, None, 0, 0.0, the empty string '', and empty collections like []. Almost everything else is truthy. This gives a tidy way to test for 'is there anything here?'. You can check with bool(value).

    Nested conditions and the one-line form

    You can put an if inside another if. Indent one more level for each. Nesting is fine for two levels, but more than that is a signal to combine conditions with and or to restructure. Python also offers a conditional expression, a one-line choice between two values: value_if_true if condition else value_if_false.

    Why Python uses indentation
    Other languages use braces and let you indent however you like, which often leads to code that looks like it does one thing but does another. Python forces the visual layout and the logic to match, so the code you see is the code that runs.
    Common mistakes
    Writing if x = 5: (assignment) instead of == gives a SyntaxError. Comparing text to a number, such as input() result against 18, never matches: '18' == 18 is False, so convert first. Using several separate if statements when you want elif: separate ifs are all checked, so two blocks can run.

    Remember this

    • Comparisons (==, !=, <, >, <=, >=) give True or False; = assigns and == compares.
    • A colon plus an indented block defines what an if, elif or else controls.
    • Python runs only the first matching branch in an if/elif/else chain, so order matters.
    • Combine tests with and, or and not; use in for membership checks.
    • Empty values and zero are falsy; everything else is truthy.

    What does 'not (True and False)' evaluate to?

    Module 5

    Loops: repeating work

    Use for and while loops to repeat actions, control them with break and continue, and build totals with the accumulator pattern.

    About 55 minutes

    Computers are good at doing the same thing a million times without getting bored. A loop repeats a block of code. Python has two kinds. A for loop goes through a known collection of things, one at a time. A while loop keeps going for as long as a condition stays true. Choose for when you know what you are looping over, and while when you do not know in advance how many repeats you need.

    The for loop

    Read for letter in word: as 'for each letter in word, do the following'. On each round, the loop variable (letter) is attached to the next item. The indented block is the body; it runs once per item.

    range(): counting loops

    To repeat something a number of times, loop over range(). It produces numbers on demand. range(5) gives 0, 1, 2, 3, 4, which is five numbers starting at zero and stopping before 5, exactly like slicing. range(start, stop) sets the first number, and range(start, stop, step) sets the jump size.

    The accumulator pattern

    One pattern appears in almost every program: start with an initial value, then update it on each pass. That gives you totals, counts, maximums, or a built-up string. Always create the accumulator before the loop. If you create it inside, it resets to the starting value on every round.

    The while loop

    A while loop checks its condition before every round. If it is true, the body runs, then Python goes back and checks again. When the condition becomes false, the loop ends. Something inside the body must eventually make the condition false, otherwise you have an infinite loop.

    Infinite loops
    If you forget the count -= 1 line above, the condition is true forever and the program never stops. If this happens, press Ctrl + C in the terminal to interrupt it. When you write a while loop, ask yourself: what line makes this condition false eventually?

    break, continue and loop else

    • break ends the loop immediately.
    • continue skips the rest of the current round and jumps to the next one.
    • else on a loop runs only if the loop finished normally, without hitting break. It is handy for 'search and report not found'.

    Nested loops

    A loop inside a loop runs the inner loop completely for each round of the outer loop. Picture a clock: the minute hand goes all the way round for every single step of the hour hand. If the outer loop runs 3 times and the inner runs 4 times, the inner body runs 12 times in total.

    Why Python loops over items, not indexes
    In many older languages you must write a counter, test it and increment it by hand just to visit each item. Python's for item in collection removes that bookkeeping and the off-by-one bugs that come with it. When you do need the position as well as the item, use enumerate(): for i, item in enumerate(items, start=1):.
    Debugging a loop
    Put a print() inside the body to watch the variables change on every round. Print the loop variable and your accumulator, run it, and compare the output with what you expected. Remove the debugging prints once it works.
    Common mistakes
    Setting the accumulator inside the loop so it resets. Off-by-one with range: range(1, 10) stops at 9, so use range(1, 11) to include 10. Changing a list while looping over it. Writing the update line outside the indented block, so it only runs once after the loop. Forgetting that continue in a while loop skips your update line and can cause an infinite loop.

    Remember this

    • Use for to walk through items and while to repeat until a condition changes.
    • range(start, stop, step) stops before stop, just like slicing.
    • The accumulator pattern: create the variable before the loop, update it inside, use it after.
    • break exits a loop, continue skips to the next round, and a loop else runs only when no break happened.
    • Every while loop needs something inside that eventually makes its condition false.

    Your turn

    What does continue do inside a loop?

    continue skips the rest of the current round and moves on to the next item or condition check.

    Your program seems stuck forever in a while loop. What do you press in the terminal?

    Ctrl + C sends a KeyboardInterrupt that stops the running program.

    Module 6

    Lists and tuples

    Store many values in order, change them with list methods, avoid the copying trap, and know when a tuple is the better choice.

    About 60 minutes

    Until now each variable held one value. Real data comes in groups: the marks of 40 students, the items in a cart, the days of a week. A list holds an ordered collection of values in one variable. You write it with square brackets and commas. Items can be of any type, and you can mix types, though most lists hold one kind of thing.

    Lists are mutable

    Unlike strings, lists are mutable: you can change them in place. Assign to an index to replace an item. The list object stays the same one in memory; only its contents change.

    List methods you will use daily

    Looping over lists

    The copying trap

    This is the most important idea in the module. Remember the 'sticky label' model of variables. When you write b = a with a list, you do not copy the list. You attach a second label to the same list. Change it through either name and both names see the change.

    Why Python shares instead of copying
    Copying a list of a million items on every assignment would be slow and wasteful. Python lets names share objects and gives you an explicit way to copy when you need one. It is a speed-versus-safety choice, and knowing it exists is what keeps you safe.

    Tuples: lists that cannot change

    A tuple is like a list but immutable. You write it with round brackets. Use a tuple for a fixed group of related values where the order has meaning, such as a coordinate (12.9, 77.6) or an RGB colour. Tuples are safe against accidental change, and they can be used as dictionary keys (lists cannot). A tuple with one item needs a trailing comma: (5,).

    Unpacking

    Unpacking spreads the items of a list or tuple into separate variables in one line. The number of names must match the number of items, unless you use * to collect the extras into a list. It also gives a classic Python trick: swapping two variables without a temporary one.

    Lists of lists (2D data)

    A list can contain other lists. This is how you store a table: each inner list is a row. To reach one cell you use two indexes, row first and then column: grid[1][2] means 'row 1, then item 2 in that row'. Loop over it with a nested loop.

    Common mistakes
    Writing x = x.sort() or x = x.append(1), which sets x to None. Removing items from a list while looping over it, which skips elements. Using b = a when you meant a copy. Getting IndexError: list index out of range by asking for index len(list). Confusing (5) with (5,).

    Remember this

    • Lists hold ordered, changeable collections; indexing and slicing work like strings.
    • Methods like append, sort and reverse change the list in place and return None.
    • b = a shares one list; use a.copy() or a[:] for an independent copy.
    • Tuples are immutable lists, good for fixed groups and for dictionary keys.
    • Unpacking assigns several variables at once, and tables are lists of lists accessed as grid[row][col].

    Module 7

    Dictionaries and sets

    Look things up by key with dictionaries, remove duplicates and compare groups with sets, and know which collection to pick.

    About 60 minutes

    A list finds things by position: 'give me item 3'. Often you want to find things by meaning: 'what is the price of chai?'. A dictionary (dict) stores key: value pairs and looks values up by key, like a real dictionary looks up a meaning by a word. Write it with curly braces. Keys must be immutable (strings, numbers and tuples work) and unique. Values can be anything.

    Why dictionaries are fast
    A dictionary does not scan every key. It uses a hash, a number calculated from the key, to jump almost directly to where the value is stored. Looking up one key among a million takes about as long as among ten. That is also why keys must be immutable: if a key could change, its hash would change and it would be lost.

    Safe lookups with get()

    d.get(key) returns the value, or None if the key is missing, with no error. You can supply your own default as the second argument: d.get(key, 0). Use it whenever a key might not exist.

    Looping over dictionaries

    Looping directly over a dict gives its keys. Use .values() for values and .items() for both at once, as pairs you can unpack in the loop header.

    Nested dictionaries

    A value can itself be a dictionary or a list. This is how you model records, and it is also exactly the shape of JSON data you will meet on the web. Chain the keys to dig in: students['asha']['marks'].

    The counting pattern

    One of the most useful dictionary jobs is counting how often things occur: letters in a word, votes, words in a document. The idea: use the item as the key and the count as the value. get(item, 0) + 1 reads 'the current count, or zero if we have not seen it, plus one'.

    Sets: unique items

    A set is an unordered collection of unique items. Duplicates disappear automatically, and checking whether something is in a set is as fast as a dictionary lookup. Write it with curly braces and no colons. An empty set must be written set(), because {} is an empty dict. Sets have no order, so you cannot index them.

    Sets shine when comparing groups. Imagine two classes and the students who joined each club. | is union (everyone), & is intersection (in both), - is difference (in the first but not the second) and ^ is symmetric difference (in exactly one).

    Which collection should I use?

    TypeOrderedChangeableDuplicatesBest for
    listYesYesAllowedA sequence of things you will add to, loop over and sort
    tupleYesNoAllowedA fixed group such as a coordinate; dictionary keys
    dictYes (insertion order)YesKeys uniqueLooking up values by a name or id
    setNoYesNot allowedRemoving duplicates, fast membership tests, group comparisons
    Common mistakes
    Using {} expecting an empty set (it is a dict). Using a list as a dictionary key: TypeError: unhashable type: 'list'; use a tuple instead. Reading a missing key with square brackets instead of get(). Assuming x in d checks values: it checks keys. Relying on a set's printing order.
    Remove duplicates but keep order
    list(set(items)) removes duplicates but loses order. To keep the original order, use list(dict.fromkeys(items)), since dictionaries keep insertion order and cannot hold duplicate keys.

    Remember this

    • A dict maps unique, immutable keys to values and finds them quickly.
    • Use get(key, default) to avoid KeyError; loop with items() for pairs.
    • The counting pattern is counts[x] = counts.get(x, 0) + 1.
    • Sets hold unique items and support union (|), intersection (&) and difference (-).
    • Pick list for sequences, tuple for fixed groups, dict for lookups and set for uniqueness.

    Module 8

    Functions

    Package code into reusable, named tools with parameters and return values, and understand scope.

    About 60 minutes

    You have already used functions: print(), len(), range(). A function is a named block of code that you can run whenever you want, as many times as you want. Writing your own functions gives you three big wins. You stop repeating yourself, you give a chunk of logic a clear name, and you can test and fix it in one place.

    Defining and calling

    You define a function with def, a name, brackets and a colon. The indented lines below are its body. Defining does not run it; it only saves the instructions under that name. You run it by calling it: write its name followed by brackets.

    Parameters and arguments

    A function becomes far more useful when you can hand it information. Parameters are the names listed in the definition; arguments are the actual values you pass in when calling. Think of parameters as empty slots, and arguments as what you put in the slots on each call.

    return: getting a value back

    print shows something on screen, but the program cannot use it afterwards. return hands a value back to the caller so it can be stored, printed, or used in further calculations. The moment Python reaches return, the function ends. A function with no return gives back None.

    Why return instead of print
    A function that returns a value is like a calculator: you give it input and get an answer you can reuse anywhere. A function that prints is stuck in one purpose: showing text. Returning keeps your logic separate from your display, which is what makes functions reusable and testable.

    Default values and keyword arguments

    A parameter with = in the definition has a default, used when the caller leaves that argument out. Parameters with defaults must come after the ones without. Keyword arguments make calls self-documenting, as in send(to='Asha', urgent=True).

    The mutable default trap
    Never use a list or dict as a default value, such as def add(item, bag=[]). The default is created once and shared between calls, so items pile up between calls. The safe habit is def add(item, bag=None): and then if bag is None: bag = [] inside.

    Returning several values

    A function can return several values separated by commas. Python packs them into a tuple, and the caller can unpack them straight into variables, which you saw in the previous module.

    Scope: where names live

    A variable created inside a function is local: it exists only while the function runs, and it cannot be seen from outside. Variables created at the top of the file are global and can be read from inside functions. If you assign to a name inside a function, Python creates a new local one rather than changing the global. Treat the function as a sealed room: pass things in with parameters, get things out with return.

    Docstrings and design rules

    The first line inside a function can be a string describing it, called a docstring. Tools and the built-in help() show it. Good functions follow a few simple rules: do one job, choose a verb-based name like calculate_total, keep it short enough to fit on a screen, and prefer returning values over printing or changing globals.

    A first look at recursion

    A function can call itself. This is called recursion, and it fits problems that break into smaller copies of themselves. Every recursive function needs a base case that stops the chain, and a step that moves toward it. The factorial of 4 is 4 * 3 * 2 * 1, which is also 4 * factorial(3).

    Common mistakes
    Forgetting the brackets when calling: greet without () only names the function and does not run it. Using print where you needed return. Putting code after a return line, which never runs. Calling with the wrong number of arguments gives TypeError: add() missing 1 required positional argument: 'b'.

    Remember this

    • def defines a function; calling it with brackets runs it.
    • Parameters are the slots in the definition; arguments are the values you pass in.
    • return sends a value back and ends the function; no return means None.
    • Defaults and keyword arguments make calls flexible; never use a list or dict as a default.
    • Variables made inside a function are local; pass data in with parameters and out with return.

    Module 9

    Files and error handling

    Read and write text files safely with 'with', and stop programs from crashing by handling exceptions.

    About 60 minutes

    Variables vanish when your program ends. To keep data, such as marks, a to-do list or settings, you save it in a file. And whenever a program touches the outside world (files, user input, networks) things can go wrong: the file may not exist, the user may type letters where you wanted a number. This module teaches both skills together because they depend on each other: files fail often, so file code needs error handling.

    Opening a file

    open(path, mode) connects your program to a file and returns a file object. The mode says what you want to do.

    ModeMeaningIf the file existsIf it does not exist
    'r'Read (the default)Reads itFileNotFoundError
    'w'WriteErases it and starts freshCreates it
    'a'AppendAdds to the endCreates it
    Mode 'w' deletes existing content
    Opening a file with 'w' wipes whatever was in it, immediately, before you write a single character. Use 'a' when you want to add to an existing file.

    The with statement

    An open file must be closed so the data is saved properly and the operating system can release it. If your code crashes between opening and closing, the file stays open. The with statement solves this: it opens the file, runs your indented block, and always closes the file at the end, even if an error happens. Always use with for files.

    Reading a file

    There are three common ways to read: read() gives the entire contents as one string, readline() gives one line, and readlines() gives a list of lines. The most idiomatic way for text files is to loop over the file object, which hands you one line at a time and works even for huge files. Each line keeps its trailing \n, so call .strip().

    Exceptions: when something goes wrong

    When Python hits a problem it cannot continue past, it raises an exception. If nothing handles it, the program stops and prints a traceback. You can handle exceptions yourself with try and except. Python runs the try block; if an exception of the named type occurs, it jumps straight into the matching except block instead of crashing.

    ExceptionTypical cause
    ValueErrorint('abc'): right type, unusable content
    TypeError'5' + 3: wrong kind of value for the operation
    ZeroDivisionError10 / 0
    IndexError[1, 2][5]: position does not exist
    KeyError{'a': 1}['b']: key does not exist
    FileNotFoundErroropen('missing.txt'): the file is not there

    The full try statement

    • try: the risky code.
    • except SomeError: runs if that error happens. You can have several, and you can name the error object with as e to print its message.
    • else: runs only if the try block had no error. Put code that depends on success here.
    • finally: runs always, error or not. It is for cleanup.
    Why catch specific exceptions
    Writing a bare except: catches everything, including mistakes in your own code and Ctrl + C, and hides the real problem. Catch the narrowest error you expect, such as ValueError, so unexpected bugs still show up loudly and get fixed.

    Validating input with a loop

    Combining a while True loop, try/except and break gives the standard 'ask until valid' pattern. The loop only ends when the conversion succeeds and the value is acceptable.

    Raising your own errors

    Use raise when your function receives something that makes no sense. This is better than quietly returning a wrong answer, because the mistake is reported where it happens.

    Common mistakes
    Opening with 'w' when you meant to append. Forgetting that file lines end with \n and then comparing 'Asha\n' to 'Asha'. Catching everything with a bare except: or writing except: pass, which silently hides bugs. Putting too much code inside try; keep it to the one or two lines that can really fail. Relative paths depend on the folder you run from, which is a common cause of FileNotFoundError.

    Remember this

    • Use open(path, mode) inside a with block so files always close properly.
    • 'r' reads, 'w' overwrites, 'a' appends; write() does not add a new line for you.
    • Loop over a file object to read it line by line, and strip() each line.
    • try/except handles named exceptions; else runs on success and finally always runs.
    • Catch specific exceptions, validate input in a loop, and raise your own errors for impossible values.

    Module 10

    Modules, pip and virtual environments

    Reuse Python's standard library, write your own modules, install third-party packages with pip and keep projects separate with venv.

    About 55 minutes

    No programmer writes everything from scratch. Python's motto is 'batteries included': it ships with a large standard library of ready-made tools for maths, dates, random numbers, files, the web and more. Beyond that there are hundreds of thousands of third-party packages written by the community. This module shows how to use all of it, and how to split your own code into files.

    What is a module?

    A module is simply a Python file full of definitions (functions, constants) that you can load into another program with import. A package is a folder of modules. When you import math, Python finds math, runs it once, and gives you a name to reach everything inside it with a dot.

    Ways to import

    You can explore any module from inside Python. dir(math) lists its contents and help(math.sqrt) shows the documentation. The official reference is at docs.python.org.

    Three standard modules you will use all the time

    Do not name your file after a module
    If you save a file called random.py and then write import random, Python imports your file instead of the real one and you get baffling errors such as AttributeError: partially initialized module 'random' has no attribute 'randint'. Choose distinct file names like dice_game.py.

    Writing your own module

    Any .py file is a module. Put related functions in one file, then import it from another file in the same folder. This keeps programs organised: one file for calculations, one for the main program. The import uses the file name without .py.

    The __name__ == '__main__' guard

    When a file is run directly, Python sets a special variable __name__ to the text '__main__'. When the file is imported, __name__ is the module's own name instead. This lets one file serve both purposes: it works as an importable toolbox, and it can also run a demo or tests when launched directly. Without the guard, importing the file would run its demo code every time.

    pip: installing third-party packages

    pip is Python's package installer. It downloads packages from the Python Package Index (PyPI) at pypi.org. You run it in the terminal, not inside Python. Use python -m pip so that you are sure pip belongs to the Python you are using (on macOS and Linux write python3 -m pip).

    Virtual environments

    Imagine two projects: one needs version 1 of a package, the other needs version 2. If both install into the same place, they fight. A virtual environment (venv) is a private folder holding its own copy of Python's settings and packages for one project. Installing into it never affects your other projects or your system Python. Create one per project, as a habit.

    Why isolate every project
    Isolation means a project keeps working next year even if you install new things for another project. It also lets you share a project: a friend creates a fresh venv, installs from requirements.txt, and gets exactly the same setup you have.

    Your next steps

    • Build the three beginner projects from this level's project list. Projects are where reading turns into skill.
    • Practise a little every day. Thirty minutes daily beats five hours once a week.
    • When you are comfortable here, move on to the Intermediate level: object-oriented programming, comprehensions, decorators, working with APIs and testing.
    • Read other people's code and the official docs. Searching for an error message is a normal part of a programmer's day.
    Common mistakes
    Running pip install and then getting ModuleNotFoundError because pip installed into a different Python than the one running your script. Use python -m pip and check that your virtual environment is activated. Forgetting to activate the venv in a new terminal window. Naming your own file after a standard module. Importing a module from a different folder without it being in the same directory or installed.

    Remember this

    • A module is a .py file; import loads it, and the standard library gives you maths, dates, random numbers and more.
    • Prefer import module or from module import name; avoid import *.
    • Use if __name__ == '__main__' so a file can be both imported and run directly.
    • pip installs packages from PyPI; use python -m pip and keep a requirements.txt.
    • Create one virtual environment per project so dependencies never clash.
